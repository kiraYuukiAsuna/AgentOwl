# AgentOwl 验证记录

本记录汇总了截至 2026-11-11 在本地开发机与测试服务器 `10.37.90.168` 上的测试范围和实际结论，方便上线前核对哪些环节已经过真机验证、哪些仍需在目标租户和生产环境实测。

- **本地检查环境**：macOS、PostgreSQL 17、Go 1.26.5、Node.js 26.4、Kiota 1.36.1。
- **测试开发机**：`10.37.90.168`（veLinux 2 / amd64 / cgroup v1 / Docker 29.9.2 / Compose 5.6.1），环境与运维方式见 [开发机部署说明](development-deployment.md)。
- **近期迭代补充**：2026-11-10 至 2026-11-11 的持续任务运行时、统一审批、审批通知、按需上下文与飞书身份绑定上线验收详情见 [实现与发布记录](task-runtime-implementation.md#迭代与发布记录)。

## 上线前待实测项

在切入正式团队和生产环境前，以下六项必须在真实目标环境中完成验证（建议先用测试群和测试仓库，并保持人工审批）：

1. **飞书 / Lark 真实租户**：核实应用安装范围、普通群与外部群权限、历史消息与话题读取、卡片操作者映射、长连接稳定性及平台限流。当前仅实现应用机器人连接器，不包含个人账号桥接。
2. **GitHub 真实仓库**：验证令牌权限、Webhook 投递、分支保护规则，以及 Draft PR 的实际创建、追加提交、Review/CI 状态回传与合并流转。
3. **真实模型供应商**：核验所选模型的工具调用稳定性、结构化 JSON 输出兼容度、Token 用量返回、超时表现，以及真实答疑和改代码的质量。
4. **OIDC 与限流**：对接团队正式 OIDC 身份源，验证登录、注销、成员绑定及 Redis 限流行为。
5. **cgroup v2 下的 Linux Runner**：开发机仅在 cgroup v1 的 `disabled` 模式下跑过容器测试；生产环境需在 cgroup v2 宿主机验证 `required` 模式的 CPU/内存/PID 硬限额、磁盘/inode 耗尽保护、真实许可中断、宿主机重启恢复，以及业务项目的真实工具链镜像。
6. **真实冷备与跨机恢复**：在目标主机做一次完整的停写备份、跨机恢复与外部操作对账演练。

## 本地复现

参考 [README](../README.md) 准备好依赖和测试数据库后执行：

```sh
export AGENTOWL_TEST_DATABASE_URL='postgres://test-user:test-password@127.0.0.1:5432/agentowl_test?sslmode=disable'
make check
script/gen-client.sh --check
```

- 测试库账号需具备建 schema 和启用 `pg_trgm` 扩展的权限；未设置 `AGENTOWL_TEST_DATABASE_URL` 时数据库测试会跳过。
- `make ci` 强制要求测试库、Docker Compose 和 Kiota 全部可用，缺任一项都会直接报错退出。
- 本地启动后的 HTTP 冒烟方式见 [README](../README.md)，开发机在线验收脚本位于远端项目的 `deploy/verify-dev-deployment.py`。
