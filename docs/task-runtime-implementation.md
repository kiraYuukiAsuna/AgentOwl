## 持久化与兼容

- `000010_task_runtime.up.sql` 添加来源、输入、revision 关联、mandate、评估、决策、事件及回执；全局接单默认 `off`。不改写既有已部署迁移。
- `000011_runtime_machine_reference.up.sql` 修正原有 `run_attempts.runtime_machine_id` 外键：运行服务实际使用 `configs` 中的宿主，旧外键却指向未使用的 `runtime_machines` 表。旧表保留；其中独有记录以禁用配置保留，需重新配置凭据后启用。
- Worker 维护扫描每次补齐最多 100 个历史来源线程，并补记最多 100 个旧任务的授权来源和会话关联。旧任务的目标、审批、产物、revision/epoch 不被重写；无法证明的历史路径范围标为缺失，后续执行需要重新确认。不会补造历史送达或消费回执。唯一约束和事务保证扫描可重跑。
- 新输入协议为 `task_input_receipts_v1`，分页能力为 `context_ref_pages_v2`。旧 spec 的新增字段均使用 `omitempty`，保持原摘要。需要新协议的 attempt 只调度到声明相应能力的宿主。
- 内部引用读取绑定 Runtime Machine 和 run；每次 Runner 输入读取重新检查当前许可。未知协议拒绝，省略 protocol 或 `protocol=1` 保留旧引用形状。
- 单条任务输入最多 64000 字节，每个修订最多采用 128 条。超限不截断、不伪报全文消费；可将旧输入改为参考信息。来源消息原有长度限制继续适用。

实施时复用了现有运行轮询和归档传输，没有再增加回执回调服务。任务状态规则返回明确的新状态，审批/步骤/attempt 的原子写入继续保留在服务事务中，没有新增通用工作流效果解释器。
