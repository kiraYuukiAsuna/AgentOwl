# External adapters

This package contains HTTP protocol adapters. It does not authorize business actions, persist jobs, execute tools, or retry external writes. Callers must enforce channel/repository permissions, approval versions, durable idempotency and task budgets.

## Lark and Feishu

- `LarkConfig.BaseURL` selects the platform API host. Tenant token acquisition uses the self-built application App ID/App Secret endpoint supported by the [official Go SDK](https://github.com/larksuite/oapi-sdk-go/blob/v3_main/service/auth/v3/resource.go). Tokens are cached until the returned lifetime minus a safety margin, with one concurrent refresh. Invalid-token errors clear the cache without replaying the failed business request.
- `ParseWebhook` handles v2 HTTP event callbacks with configured `AppID`, `TenantKey`, `VerificationToken` and `EncryptKey`, and also accepts card button callbacks on the same hook for deployments that can only expose one callback endpoint. `ParseCardAction` handles the dedicated `/actions` hook using the platform token signature, and also accepts v2 card-action payloads there. Both normalize to the same `CardAction` business path. URL verification only returns a challenge after credential validation. Webhook signatures, AES-CBC cipher format and clock windows follow the official SDK.
- `CardAction.ActorTenantID` is the operator's tenant; `TenantID` is the owning application tenant. `Value` and `FormValue` are untrusted inputs. A valid callback is not an approval: map the verified operator to a member and check the action, object, version and scope in the business service.
- `History` fetches one bounded page. Persist the returned cursor and obtain thread replies separately. It intentionally rejects time filters for thread history, matching the [history API](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list). User-identity authorization and refresh are not implemented by this application-bot client.
- `SendMessage` requires a caller-persisted UUID and never retries. A known remote message ID can be looked up; a UUID-only ambiguous send cannot be reliably looked up through these APIs. The platform's time-bounded UUID deduplication does not replace an external-operation ledger. See the [send-message API](https://open.feishu.cn/document/server-docs/im-v1/message/create).
- A recalled message may lack a chat ID; resolve its existing source record before applying channel authorization. `Ignored` means an authenticated event type that this adapter does not handle.

## GitHub

- Clients are scoped to one configured owner/repository. Webhooks use HMAC-SHA256 over the exact body, checked against the [official verification format](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries).
- Delivery headers are not authenticated by that body signature. `Event.ID` therefore uses the signed-body SHA-256; `DeliveryID` remains available for diagnostics. Persist the event/message identity to reject replays. Source `updated_at` does not establish delivery order; delete events receive a distinct revision, and uncertain ordering requires an authoritative read.
- API version `2022-11-28` is pinned; GitHub currently [supports it through March 10, 2028](https://docs.github.com/en/rest/about-the-rest-api/api-versions). Each list call returns one bounded page; callers continue pagination. Commit statuses and check runs are separate APIs and must both be evaluated for CI coverage.
- Git database reads verify blob SHA-1 and reject truncated trees. Create/update operations never force-push. Git object creation is a remote write and requires approval before calling. The publisher must enforce allowed branches/paths and verify the resulting tree against its frozen manifest. See [trees](https://docs.github.com/en/rest/git/trees), [blobs](https://docs.github.com/en/rest/git/blobs), and [references](https://docs.github.com/en/rest/git/refs).
- Issue/comment/PR creation has no assumed idempotency guarantee. Correlation markers and PR queries support reconciliation; an absent lookup result does not prove a previous request failed. `APIError.OutcomeUnknown` must keep ambiguous operations from being blindly retried.

## Model and credentials

- `ModelClient` calls the configured `BaseURL + /chat/completions`. No provider SDK or default external model is chosen. The wire format follows [Chat Completions](https://platform.openai.com/docs/api-reference/chat/create); compatibility must be verified against the selected provider.
- `Complete` validates tool names, JSON arguments, response shape, finish reason and usage. JSON Schema support is an explicit subset in `schema.go`; unsupported keywords fail before the request. `Classify` and `Answer` additionally validate their typed outputs, and answers cannot cite evidence IDs that were not provided. Schema validity and valid citations do not by themselves prove factual correctness or authorize sending.
- Providers must return `prompt_tokens`, `completion_tokens` and `total_tokens`; missing usage is not treated as zero-cost success. `json_object` or `max_completion_tokens` must be configured explicitly when required by the provider. There is no silent request-format fallback or automatic model retry.
- HTTP requests have bounded timeout/body size, expose bounded, redacted upstream status, error code, request ID and selected diagnostic messages while suppressing raw upstream bodies, and reject redirects for standard `http.Client` instances. A custom injected `HTTPDoer` must respect request cancellation and must not follow redirects. Remote plaintext HTTP requires explicit configuration; loopback HTTP is accepted for local testing.
- `Vault` uses AES-256-GCM with fresh nonces and caller-provided associated data. Bind associated data to the credential owner and key version; key storage/rotation belongs to deployment and business services. `Redact` removes supplied secrets and common patterns, but it is not a complete secret detector. Do not forward unnecessary source text or credentials to models or logs.

`integration_test.go` exercises simulated HTTP endpoints and security failure cases. It makes no real platform writes and does not establish tenant, real-repository, or model-provider validation.
