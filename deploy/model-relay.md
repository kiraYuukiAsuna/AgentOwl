# 从容器访问宿主机本地模型服务

如果模型服务只监听在宿主机的 `127.0.0.1`，Docker 容器里的 `127.0.0.1` 指向的是容器自身，无法直接连通。在 Linux 开发机上可以运行 `deploy/model-relay.py`，把 Docker 网桥网关上的端口转发到宿主机的本地模型端口。

## 配置步骤

1. 运行 `docker network inspect bridge` 查看默认网桥的网关 IP，确认模型服务实际监听的端口。下方示例把 `172.17.0.1:18317` 转发到 `127.0.0.1:8317`（切勿监听 `0.0.0.0`）。
2. 参考 `deploy/model-relay.service.example`，按实际用户名、项目路径和端口修改后安装为 systemd 服务并设为开机自启；模型服务本身也应单独配置开机自启。
3. 在 AgentOwl「设置 → 模型接口」中将 API 地址改为网桥地址，例如把 `http://127.0.0.1:8317/v1` 改成 `http://172.17.0.1:18317/v1`；更改地址后按页面提示重新填写 API 密钥。
4. 从 Worker 容器网络测试接口连通性，并做一次问题分类验证。若后续调整了 Docker 默认网桥网段，记得同步修改转发服务和模型接口地址。

> 安全提示：尽管转发只绑定在指定的 Docker 网桥地址，但宿主机上其他能访问该网桥的容器或进程同样能触达此端口。请确保模型服务开启鉴权，并注意网桥上的 HTTP 流量本身不加密。
